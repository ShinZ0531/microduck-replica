# 头部 BMI088 通电站姿核验

当前流程为 2026-11-16 完成的通电站姿版本，替代此前难以单人操作的断力手扶方案。
适用固定模型的头部 HAT BMI088 与头颈 ID30/31/32/33；机械零位沿用现有配置，不重做。

## 操作流程

先进入 Studio 的 IMU 页，确认主控在线且处于标定模式。

1. 使用原来的“站姿使能”，让鸭子通电站在平桌上。等待站姿保持完成；此处是位置保持，不运行走路策略。
2. 在“头部 BMI088 · 通电站姿核验”确认条件，点击“开始整机站姿采集”。三秒准备后自动采初始静止段。
3. 双手握躯干，稍微提起整只鸭子；按提示依次前倾、后倾、左倾、右倾约 15–20°，各停稳约两秒。
   每次先回到站姿端平并停半秒，再向下一方向倾斜。头颈由舵机保持，不需手扶头部，也不需逐步点击采集。
4. 第一段完成后，放回桌面，继续保持站立。确认头颈约 ±5° 内没有干涉后，单独点击“开始自动头部测试”。
5. 程序先自动采集桌面站姿基准，再逐个测试 ID30–33；每个关节约八秒缓慢经过中心→一侧→另一侧→中心，
   各关节间留三秒准备时间。其余关节维持站姿；正常情况下可在桌面自行采集，有晃动时扶稳躯干。
6. 全部通过后，单独确认“保存安装与补偿核验结果”。保存时仍保持通电站姿，策略运动开关仍关闭。
7. 扶稳鸭子后使用“失能 / 卸力”，再回上手清单预览并明确“写进主程序”。此后坐站与行走另行验收。

初始摆正依据实际机身姿态；尚未校准的 IMU 显示不能作为真实水平的证明。
首次采集采用明确提示顺序，避免依赖旧安装方向把前倾误识别成左倾。

## 停止、重试和失效

“停止采集 / 测试”停止当前轨迹，将测试关节目标冻结在可用的实测位置，保留通电站姿和已通过进度。
它不会自动回中心。正常取消核验也保留站姿；紧急卸力沿用原来的全关节卸力入口，鸭子会软下来。

页面前台每秒查询会话，查询仅续租和读取。超过 2.5 秒没有续租，主控停止轨迹；恢复网页不会自动恢复动作。
离页或隐藏页面会停止续租。重试需要用户再次明确确认，且主控仍须保持站姿。
当前步骤超过一分钟、数据不新鲜、目标跟随误差超过约 3°或核验超差也会停止或等待。
通信故障、服务停止和紧急卸力继续走原生保护逻辑；“保留站姿”只描述正常停止和页面失联时的行为。

IMU 源 epoch 改变、头颈几何配置改变或会话超过十分钟会使未保存会话失效。
取消和重启不保留未完成会话；更改安装、零位或方向后，不能借用旧的安装证明。

## 数据流和职责

`web/imu.js` 保留原站姿入口；`web/head-calibration.js` 显示两阶段提示、倒计时、停止和明确保存。
`studio/imu.py` 仅转发操作，页面不能上传采样、候选四元数或通过标志。

主控 `head_imu_standing.rs` 独占会话、前台续租和头部目标调度；实际串口仍只由 commissioning 的 Hold 写入。
它与原有站姿保持共用一套目标，避免两个控制器争抢舵机。
主控从 tofd 原始 IMU 与真实编码器历史取样；`head_calibration.rs` 管理 C ABI、时效和证明文件。
C++ `head_calibration.cpp` 复用原估计器的时间对齐与头颈运动学，求解传感器到模型头部的安装变换并计算残差。

整机摆正、前倾、左倾用于求安装；后倾检查与前倾相反，右倾是未用于求解的方向复核。
桌面重新站稳后再采独立基准。四个关节的动态测试检查头部运动是否被正确扣除；
偏航也检查运动过程中的角速度及相对旋转，不能只凭重力看起来水平就通过。

本地控制器为 `control.48-head-bmi088.4`、IPC API45；校准 C ABI v2 状态为 352 字节，估计 ABI v1 不变。
不是 RC4 升级，不改策略模型，不重新烧 TF 卡。

## 计算门限与限制

以下是当前工程条件，尚需真实操作评估重复性，不是传感器厂家精度认证。

| 检查 | 条件 |
| --- | --- |
| 通用采样 | 至少 60 帧、跨度至少 1.5 秒；静止窗口两秒、头部运动窗口六秒，最多 350 帧 |
| 连续性 | 源间隔超过 100 ms 清空当前窗口；过期样本不能推进或保存 |
| 静态安装采集 | 重力分散≤1.5°、角速度范数≤0.08 rad/s；头颈由舵机保持，与初始反馈变化≤2° |
| 先回正 | 相对初始重力夹角≤5°，连续 25 个有效样本；不依赖旧安装轴标签 |
| 整机倾斜 | 12–35°；前后反向误差≤20°，前倾/左倾正交误差≤12°，独立右倾方向误差≤20° |
| 桌面站姿基准 | 补偿身体倾斜≤5°，静止变化≤1.5°、角速度 RMS≤0.08 rad/s |
| 单关节反馈 | 行程≥8°，其余头颈关节变化≤3°；轨迹相对当前保持中心约 ±5° |
| 动态姿态补偿 | 窗口内身体姿态变化≤5°；角速度残差 RMS≤0.15、峰值≤0.5 rad/s |
| 小幅角速度补偿 | 约十帧均值后的残差/预期头部角速度能量平方根比≤0.5，预期角速度 RMS≥0.01 rad/s |

相对角速度检查用于避免慢速小幅动作中“陀螺读数全零仍落在绝对容差内”的假通过。
它还受反馈计数量化、同步误差和真实机身晃动影响；失败不能直接归因为关节方向反了。
六轴 IMU 没有绝对航向，动态检查比较当前窗口的姿态变化。
本流程不校准加速度计比例/零偏或陀螺温漂，也不消除头部平移加速度对融合的影响。
通过这里不能证明快速摆头、强化学习输入分布或走路效果已正确。

## 保存与主程序提交

只有完整原生实测报告才能保存。校准文件仍为 `/etc/robot/feetech-ft5/hd1910-calibration.toml`，
旁边 `hd1910-calibration.head-imu-proof.json` 保存协议 `head_mount_standing_v2`、十步数据、安装旋转、模型摘要和头颈配置。
旧手扶协议不能充当新版自动站姿测试的证明。保存保留零位和方向，`motion_enabled=false`；
C++ `motionAuthorized` 恒为 0，仅原生用户确认的标定动作可以控制头部。

报告绑定模型及四个头颈关节的 ID、名称、零位、方向和保存的安装旋转。
上手清单提交保留这些几何值和已有限位，仅沿原有规则填补缺失的标准限位及校准完成标志。
helper 必须再次检查原生证明、断力就绪及无活动核验，才切换已知 `.4` 服务覆盖的 commissioning 参数。
提交失败恢复原校准、证明和覆盖。未知服务覆盖不猜测修改；固定躯干 `verify-imu` 对头部的拒绝继续保留。
