# 头部 BMI088 专用安装核验

本次补齐 Studio、原生主控和 C++ 核验器之间缺失的闭环。适用当前固定模型的头部 HAT
BMI088 与头颈 ID 30/31/32/33；不把普通固定躯干 IMU 的校准结果当作头部安装证明。

## 责任和数据流

`web/head-calibration.js` 显示步骤、确认和结果；`studio/imu.py` 只转发操作。
主控 `feetech_commissioning.rs` 独占会话，从 tofd 真实源时间帧及原有舵机反馈历史取样。
`head_calibration.rs` 负责 C ABI、时效、会话失效、报告及文件绑定；
`source/head_calibration.cpp` 复用原估计器的编码器对齐和头颈运动学，完成安装求解和误差判定。
页面只允许开始、查询、采集、保存或取消，不能提交采样或候选四元数。

控制器是 control.48 的本地 `.3` 扩展，IPC API 43→44；旧估计 C ABI v1 不改布局，
新校准 ABI 独立，状态结构 344 字节。没有切换 RC4、改策略模型或重新烧卡。

## 实物操作

已完成的舵机机械零位不重做。先进入 Studio 的 IMU 页，确认主控在线且处于标定模式。
全过程舵机断力，需承托躯干和头部，避免自由垂落、夹手及机械限位。程序不会自动转动关节。

1. 托住整只鸭子，躯干摆正，头颈固定；停稳至少两秒，采初始姿态。
2. 头颈相对躯干姿态不变，整个机身前倾约 15–30°，停稳后采集。
3. 同样保持头颈，整个机身向鸭子自己的左侧倾斜约 15–30°，停稳后采集。
4. 重新摆正躯干并固定，独立采集复核基准。
5. 固定躯干，只缓慢手动转动 ID30 颈俯仰，往返行程至少 8°，随即采集。
6. 固定躯干，只缓慢手动转动 ID31 头俯仰，随即采集。
7. 固定躯干，只缓慢手动转动 ID32 头偏航，随即采集。
8. 固定躯干，只缓慢手动转动 ID33 头横滚，随即采集。
9. 头颈固定在任一模型允许姿态，整个机身前倾约 15–30°，停稳后采集。
10. 整个机身向左倾斜约 15–30°，停稳后采集。

每步须明确确认，未通过留在当前步骤并显示原因；不要为了通过而修改零位或关节方向。
最后单独点击“保存头部核验结果”。保存后回总览“上手清单”，先预览，再明确“写进主程序”。
这一步才会沿原有提交流程转换到运动模式，不等于坐站或行走测试已经完成。

采安装方向的前三步依赖操作者正确识别机身正向和左侧，并保持头颈相对姿态。
后续四个关节的独立运动检查补偿能否消除头部变化，最后两次倾斜检查躯干输出方向。
任意三次静止姿态不能证明头部关节方向正确，因此不能只算一个安装四元数后直接放行。

## 门限与限制

这些门限是本轮工程验收条件，需要实物数据进一步评估，不是厂家精度认证。

| 检查 | 当前条件 |
| --- | --- |
| 通用采样 | 至少 60 帧、跨度至少 1.5 秒；静止取最近 2 秒、关节运动取最近 6 秒，最多 350 帧 |
| 连续性 | 源采样间隔超过 100 ms 清空当前窗口；过期数据不能用于推进或保存 |
| 安装静止段 | 重力分散不超过 1.5°、角速度范数不超过 0.08 rad/s，头颈相对初始变化不超过 2° |
| 安装倾斜 | 12–35°；前倾/左倾构成的方向正交误差不超过 12° |
| 独立摆正复核 | 补偿躯干倾斜不超过 5° |
| 单关节运动 | 当前关节行程至少 8°，其余关节变化不超过 3° |
| 运动补偿 | 同一窗口内躯干四元数变化不超过 5°；角速度残差 RMS≤0.15、峰值≤0.5 rad/s |
| 整机复核 | 静止变化≤1.5°、角速度 RMS≤0.08 rad/s；倾角 12–35°、倾斜方向误差≤20° |

六轴 IMU 没有绝对航向。关节运动检查比较各自窗口内的躯干变化，避免把步骤之间的航向漂移
当成安装变化；仍会拒绝窗口内过大的漂移或振动。安装求解以重力和已知整机倾斜方向为依据。
本流程不校准加速度计比例/零偏、陀螺仪温漂，也不消除头部平移加速度对姿态融合的影响。
通过安装检查不能证明快速摆头时的精度，也不能证明强化学习策略输入分布匹配。

## 保存、提交和回退

主控仅在断力、无其他移动/校验任务且十步完整时接受保存。
校准文件仍是 `/etc/robot/feetech-ft5/hd1910-calibration.toml`；
旁边的 `hd1910-calibration.head-imu-proof.json` 保存原生十步报告、安装旋转、模型摘要和头颈配置。
保存安装时保持 `motion_enabled=false`。C++ 的 `motionAuthorized` 始终为 0。

报告绑定冻结模型和四个头颈关节的 ID、名称、零位、方向以及保存的安装旋转。
修改这些几何条件后旧报告失效；舵机 calibrated 标志、运动开关和限位字段不作为安装几何绑定。
上手清单提交保留所有零位/方向和已有限位，仅沿原有规则填补缺失的标准限位及校准完成标志。
不允许页面另给一组安装旋转或关节方向替代已经核验的数据。

会话在 IMU 源 epoch 变化、头部几何配置改变或超过十分钟时失效；断流会重建当前采样窗口。
取消或重启不保留未完成会话。完整保存的报告留在设备，不进入通用镜像或 Git。
缺失或不匹配的报告会阻止 head 来源进入运动模式，即使手动改 verified 也不能代替校验。

受保护 helper 在提交前重新读取主控报告并检查断力、就绪、无活动校验。
仅切换已知 `.3` 本地服务覆盖中的 commissioning 参数；未知覆盖不会被猜测修改。
原校准、报告和服务覆盖进入事务备份；重启或回读失败恢复原配置。
原有固定躯干 `verify-imu` 对头部来源的拒绝继续保留，普通固定式 IMU 流程不变。

- C++ 原估计器 1693 与专用校验器 6554 个断言通过，包含完整十步、方向错误、未运动、缺数据和禁止跳步。
- 选定原生目标 780 项唯一 Rust 测试通过，显式执行动态 ABI、ONNX 和隔离模式切换等 ignored 用例。
- Python 原 IMU/提交/上手清单回归，以及新增八项头部专用测试通过；验证几何保留、报告绑定、拒绝伪造及失败回退。
- 隔离 Chrome 的模拟控制器十步流程通过；一次故意失败不推进、必须单独保存、离页停止轮询、移动宽度无溢出。
- 三个补丁顺序重建的 24 个原生目标文件与实际构建源码逐字节相同。
