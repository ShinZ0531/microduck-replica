# 头部 BMI088 通电站姿核验

当前为 2026-11-16 的停稳端点版本：通电站姿、原有圆圈引导的整机采集，随后自动测试头颈。
途中允许舵机卡顿，以停稳端点姿态为主、三个单向累计旋转为辅，不要求瞬时角速度一致。
适用固定模型的头部 HAT BMI088 与头颈 ID30/31/32/33；机械零位沿用现有配置，不重做。

## 操作流程

先进入 Studio 的 IMU 页，确认主控在线且处于标定模式。

1. 使用原来的“站姿使能”，让鸭子通电站在平桌上。等待站姿保持完成；此处是位置保持，不运行走路策略。
2. 在“头部 BMI088 · 通电站姿核验”确认条件，点击“开始整机站姿采集”。三秒准备后自动采初始静止段；身体阶段复用旧的实时方向圆圈、完成点、倾角、提示音及 3D 引导。
3. 双手握躯干，稍微提起整只鸭子；按提示依次前倾、后倾、左倾、右倾约 15–20°，各停稳约两秒。
   每次先回到站姿端平并停半秒，再向下一方向倾斜。头颈由舵机保持，不需手扶头部，也不需逐步点击采集。
4. 第一段完成后，放回桌面，继续保持站立。确认头颈约 ±5° 内没有干涉后，单独点击“开始自动头部测试”。
5. 程序先自动采集桌面站姿基准，再自动测试 ID30、ID31、ID33；每个关节先回中位，再经过中位→一侧→另一侧→中位；
   ID32 偏航按当前设置**跳过**（不移动、不采集、不伪造通过），报告中明确标为 `skipped_yaw_v1`；
   每个端点等待反馈连续一秒停稳后才进入下一段，通常约 14 秒，卡顿或等待会延长。各关节间留三秒准备时间。其余关节维持站姿；正常情况下可在桌面自行采集，有晃动时扶稳躯干。
6. 全部通过后，单独确认“保存安装与补偿核验结果”。保存时仍保持通电站姿，策略运动开关仍关闭。
7. 扶稳鸭子后使用“失能 / 卸力”，再回上手清单预览并明确“写进主程序”。此后坐站与行走另行验收。

初始摆正依据实际机身姿态；尚未校准的 IMU 显示不能作为真实水平的证明。
首次采集采用明确提示顺序，避免依赖旧安装方向把前倾误识别成左倾。

## 停止、重试和失效

“停止采集 / 测试”停止当前轨迹，将测试关节目标冻结在可用的实测位置，保留通电站姿和已通过进度。
它不会自动回中心。正常取消核验也保留站姿；紧急卸力沿用原来的全关节卸力入口，鸭子会软下来。

页面前台每秒查询会话，查询仅续租和读取。超过 2.5 秒没有续租，主控停止轨迹；恢复网页不会自动恢复动作。
离页或隐藏页面会停止续租。重试需要用户再次明确确认，且主控仍须保持站姿。
当前步骤超过一分钟、数据不新鲜、目标跟随误差超过约 3°或端点等待超过六秒也会停止。
头部失败只重试当前关节：先回中位，清空旧轨迹，再采一组独立端点；已通过的整机与关节结果保留。
通信故障、服务停止和紧急卸力继续走原生保护逻辑；“保留站姿”只描述正常停止和页面失联时的行为。

IMU 源 epoch 改变、头颈几何配置改变或会话超过十分钟会使未保存会话失效。
取消和重启不保留未完成会话；更改安装、零位或方向后，不能借用旧的安装证明。

## 数据流和职责

`web/imu.js` 保留原站姿入口；`web/head-calibration.js` 显示两阶段提示、倒计时、停止和明确保存。
`studio/imu.py` 仅转发操作，页面不能上传采样、候选四元数或通过标志。

主控 `head_imu_standing.rs` 独占会话、前台续租和头部目标调度；实际串口仍只由 commissioning 的 Hold 写入。
它与原有站姿保持共用一套目标，避免两个控制器争抢舵机。
主控从 tofd 原始 IMU 与真实编码器历史取样；`head_calibration.rs` 管理 C ABI、时效和证明文件。
C++ `head_calibration.cpp` 复用时间对齐和头颈运动学求安装；`head_endpoint_verification.cpp` 独立计算
四停稳端点的机身姿态差及三段陀螺累计旋转误差，Rust/Python/JS 不重复实现测量算法。

整机摆正、前倾、左倾用于求安装；后倾检查与前倾相反，右倾是未用于求解的方向复核。
桌面重新站稳后再采独立基准。四个关节都检查扣除关节运动后的停稳机身姿态。
每个单向区间按源时间戳积分传感器局部角速度，并扣除两端静止偏置均值，与实测关节运动学预测的完整旋转比较。
三段分别核对，不能用整趟往返相互抵消；全零陀螺或反向轴不能通过。
偏航（ID32）在当前版本按操作者要求跳过：重力对偏航没有绝对参考，站立机身的偏航又不受约束，
端点/积分检查无法区分补偿误差与机身反扭矩，因此不再把它当作安装通过条件；
报告保留一条零证据的 `skipped_yaw_v1` 记录，页面显示“已跳过”，不能读成实测通过。
这意味着保存后的核验**不证明偏航角速度扣除正确**；策略的 body yaw 硬编码为零、不会消费绝对偏航，
但偏航角速度仍进入观测，后续动作验收需单独关注。

本地控制器为 `control.48-head-bmi088.5`、IPC API45；校准 C ABI v2 状态为 352 字节，估计 ABI v1 不变。
不是 RC4 升级，不改策略模型，不重新烧 TF 卡。

## 计算门限与限制

以下是当前工程条件，尚需真实操作评估重复性，不是传感器厂家精度认证。

| 检查 | 条件 |
| --- | --- |
| 通用采样 | 至少 60 帧、跨度至少 1.5 秒；整机静止窗口两秒、头部完整轨迹最多 40 秒/2200 帧 |
| 连续性 | 源间隔超过 100 ms 清空当前窗口；过期样本不能推进或保存 |
| 静态安装采集 | 重力分散≤1.5°、角速度范数≤0.08 rad/s；头颈由舵机保持，与初始反馈变化≤2° |
| 先回正 | 相对初始重力夹角≤5°，连续 25 个有效样本；不依赖旧安装轴标签 |
| 整机倾斜 | 12–35°；前后反向误差≤20°，前倾/左倾正交误差≤12°，独立右倾方向误差≤20° |
| 桌面站姿基准 | 补偿身体倾斜≤5°，静止变化≤1.5°、角速度 RMS≤0.08 rad/s |
| 单关节反馈 | 行程≥8°，其余头颈关节变化≤3°；轨迹相对当前保持中心约 ±5° |
| 端点反馈调度 | 目标误差≤6 count，连续一秒位置范围≤4 count；每端点等待最多六秒 |
| 端点测量窗口 | 至少 0.6 秒/21 帧；头颈各关节位置范围≤0.5°、传感器姿态变化≤1°、原始陀螺 RMS≤0.08 rad/s |
| 四端点几何 | 中位、两侧、回中位独立停稳；相邻单向行程≥3.5°，两侧分居初始中位两边，最终回中误差≤1° |
| 停稳姿态补偿 | 扣除实测头颈姿态后，各端点机身姿态与初始端点差≤3° |
| 单向累计旋转 | 三段各自的陀螺积分旋转与模型预测旋转之差 / 预测转角≤0.5；任一源采样间隔>60 ms 拒绝 |
| 途中角速度 | 仍报告补偿残差 RMS 和峰值，仅诊断，不作为安装校验门限 |

端点与单向积分按同一组真实采样计算，不保证修复舵机实际卡顿，也不证明逐帧角速度补偿已满足策略控制要求。
`max_body_error_deg` 现为端点姿态差；新报告用 `gyro_integral_error_ratio` 明确表示三段中最大的累计旋转相对误差。
未测字段保持未知，不再用 0° 代替。50% 是当前小幅台架的工程相对容差，仍需实机评估重复性。
六轴 IMU 没有绝对航向，动态检查比较当前窗口的姿态变化。
本流程不校准加速度计比例/零偏或陀螺温漂，也不消除头部平移加速度对融合的影响。
通过这里不能证明快速摆头、强化学习输入分布或走路效果已正确。

## 保存与主程序提交

只有完整原生实测报告才能保存。校准文件仍为 `/etc/robot/feetech-ft5/hd1910-calibration.toml`，
旁边 `hd1910-calibration.head-imu-proof.json` 保存协议 `head_mount_endpoints_v3`、十步数据、安装旋转、模型摘要和头颈配置。
旧手扶和连续扫动协议均不能充当四端点与三段积分的证明。每个头部报告须包含新方法标识、4 个端点、3 个区间，
以及 `rate_quality=diagnostic_only`，明确瞬时角速度没有被此流程认证。保存保留零位和方向，`motion_enabled=false`；
C++ `motionAuthorized` 恒为 0，仅原生用户确认的标定动作可以控制头部。

报告绑定模型及四个头颈关节的 ID、名称、零位、方向和保存的安装旋转。
上手清单提交保留这些几何值和已有限位，仅沿原有规则填补缺失的标准限位及校准完成标志。
helper 必须再次检查原生证明、断力就绪及无活动核验，才切换已知 `.6` 服务覆盖的 commissioning 参数。
提交失败恢复原校准、证明和覆盖。未知服务覆盖不猜测修改；固定躯干 `verify-imu` 对头部的拒绝继续保留。

## 验证边界

本地及板端数学测试、模拟网页流程和实际网页只读验收分别记录于
[整合记录](head-imu-integration-20261113.md)。程序部署、真实安装通过、自动头部动作和行走验收分别报告。

## 本地验证（2026-11-16）

- 合成连续运动与每 240 ms 跳动一次的运动都能通过端点协议；后者瞬时残差 RMS 超过旧 0.15 门限。
- 三个实际测试关节的反向反馈、全零陀螺、缺少末端停稳、100 ms 采样缺口、冻结姿态与反向陀螺被拒绝。
- 偏航只能在步骤 8 跳过，且只产生零证据标记；换到别步、带测量值或缺少标记都会被拒绝。
- 失败清空当前轨迹后可重试，不跳步、不复用失败数据；空会话不通过，未测行程保持未知。
- 本机浏览器验证原圆圈跟随、主控进度点亮、手机布局、明确开始头部测试、停止不自启、失败不推进、保存与离页停止轮询。
- 这些是本地数学、模拟主控与浏览器结果，实物停稳重复性和走路仍须另行验收。
